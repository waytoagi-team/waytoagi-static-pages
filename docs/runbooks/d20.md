# D20 路径接入

正式入口：`https://www.waytoagi.com/d20/`。源码：`waytoagi-team/d20` 根目录，生产文件只有 `index.html` 与 `assets/`；清单锁定完整 SHA，排除说明文档。维护归属沿用 Noodles。

## 路由与资源

- `www /d20/` 和子路径回源 `static-origin.waytoagi.com`，保留完整 URI。
- 复用 d20 原域名规则 `rule-3tbtnbo8njz2`，原位改为生成器管理的 `www.waytoagi.com /d20/* static-pages origin`；不要同时创建另一条同名前缀规则。
- `www /d20` 在现有共享入口规则 `rule-3umlkdq1t94p` 中 308 到 `/d20/`，保留查询参数。Pages 自带补斜杠目前会丢参数，不能替代此分支。
- `d20.waytoagi.com` 的 HTTP/HTTPS 请求在共享入口规则中跳到 HTTPS www：`/`、`/index.html` 对应 `/d20/`；其他路径追加 `/d20` 前缀，查询参数完整保留。
- 旧域名先 302 验证，再改为 301。保留 DNS、EO 域名接入和证书续期，以兼容历史链接。
- `routes plan` 会提示共享入口规则也匹配 `/d20/`，这是保留参数和旧域名跳转所必需的；**不要停用或删除共享入口规则**。
- 11 个视频由既有构建器转存到内容哈希命名的 OSS 对象，原相对路径 302 到 `www /_media/*`，复用现有媒体规则，验证 Range 和播放。

本次只接入 d20；现有三个静态页规则的共享合并仍是独立工作。原位接管使本次不新增顶层 EO 规则。

## 发布与切换

1. 以 pending 挂载构建，比较所有生产文件与旧 OSS 内容；通过静态检查、凭证扫描、浏览器检查。
2. 确认其他挂载与线上发布清单一致，再部署 Pages 并校验 `/d20/` 源站内容。
3. 先补 www 裸路径跳转，再将原 d20 规则原位改为生成器的目标规则；为 `/d20` 裸路径和 `/d20/` 目录清缓存并验收正式入口。
4. 新入口通过后启用旧域名 302，验收路径、参数、资源及视频后改为 301。旧域名切换时清除其既有缓存。
5. 清单改为 active；不能依赖“只改状态”自动触发部署，应显式运行正式地址校验与切流缓存清理。
6. 将源仓库变量 `OSS_DEPLOY_ENABLED` 改为 `false`，停止旧 OSS 自动发布。旧工作流手动入口仅作回退，旧内容至少保留一周。

后续更新：源仓库合并页面或资源 → 本仓库自动产生 bump PR，或手动更新固定 SHA → CI 审核后合并 → 统一 Pages 发布。向源仓库 push 不再直接更新线上路径。

## 验收与回退

验收覆盖 32 页、11 个视频、前后按钮与键盘、桌面/手机、全部资源摘要、视频 Range/拖动、裸路径、index.html、带参数入口和旧域名跳转。其他三个挂载与主站入口需回归。

优先回退本仓库的 d20 固定 SHA 并发布。已发出的 301 可能留在浏览器，不能只撤销旧域名跳转后删除 `/d20/`。源站不可用时，可用原规则 ID 临时将 `www /d20/*` 回源旧 `d20-oss.waytoagi.com`，移除 `/d20` 前缀；旧源 HTTPS 证书域名不匹配，回退沿用原 HTTP 回源。恢复期间暂停该前缀的 routes apply，防止生成器覆盖临时回退；保留其他挂载及媒体哈希对象。

完整规则快照、文件核对与实施记录保存在维护者本地受限目录，不提交私有回源参数。
